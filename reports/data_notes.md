# 데이터 노트 — Gehler-Shi (SFU 재처리판)

## 구성
- PNG 568장, 선형 12비트(uint16에 저장)
- Canon 1D 86장(`8D5U…`, 1359×2041, 블랙 레벨 0) / Canon 5D 482장(`IMG_…`, 1460×2193, 블랙 레벨 129)
- 정렬 순서 = 1D 86장 → 5D 482장 (설명서 순서와 일치)
- `colourchecker_gamma1_bit12.mat`: 사진별 24칸 평균 색 (568×24×3, 블랙 레벨 미적용)
- `real_illum_568..mat`: 사진별 조명 정답 (568×3)
- 정답 조명 = (24칸 − 블랙 레벨)의 19~24번 칸 채널별 최댓값(NaN 제외) → 재계산 오차 0 확인
  (채널별로 따로 고르는 방식이라 알려진 문제가 있음 → 아래 "정답 조명의 한계")

## 빈칸(NaN)
- 1,204칸이 칸 통째로 비어 있음 → 채점 가능 12,428 / 13,632 (91.2%)
- 모든 사진에 쓸 수 있는 칸이 남음 (사진당 빈칸 최대 22개)
- 5D(61% 사진)에 1D(26%)보다 훨씬 많음
- 검정 304 · 파랑 161 · 빨강 105 등 "가장 어두운 채널"이 약한 칸에 집중
- **규칙 확인**: 빈칸은 "어둡거나 포화된 칸"이다
  - 어두운 칸: 블랙 레벨을 뺀 뒤 가장 어두운 채널이 20 미만인 칸을 비움
    (남은 칸의 최솟값이 1D·5D 모두 정확히 20.0) → 신호가 전체의 약 0.5% 미만인 칸 제외
  - 포화된 칸: 흰색(19번)이 빈 9장(1D 4 · 5D 5) 모두, 남은 회색 칸으로 추정한 흰색 원본 값이
    포화 기준 3,300 이상 → 너무 밝아서 뺀 것. 그중 3장은 20번도 같은 이유로 비어 있음
    (`10_check_camera_white.py` Y5, 2026-10-28). 흰색은 회색 칸보다 항상 밝아서 "어두워서"일 수 없음
  - 대부분은 어두운 칸이고, 포화로 확인된 것은 적어도 12칸(흰색 9 + 20번 3)
- 5D에 빈칸이 많은 것은 같은 기준에서 5D 장면이 더 어두웠기 때문

## 처리 규칙 (평가 전 고정)
- 빈칸 칸만 채점 제외, 사진은 568장 유지
- 리포트에 색별 채점 가능 문제 수 함께 표기
- 한계: 빈칸이 어두운 색에 몰려 정답률이 실제보다 높게 나올 수 있음
- 앱에서도 같은 기준 적용 검토: 가장 어두운 채널 < 20이면 "판단 불가"로 답하기
  (아주 밝은 칸도 포화될 수 있으므로 "너무 밝아 판단 불가"도 함께 검토)
- 포화 의심 판단(`common.load_gehler_index`)은 **칸 평균값** 기준(블랙 레벨 더한 값 > 3,300)이다.
  우리는 24칸의 평균만 가지고 있어서, 평균이 기준 아래여도 칸 안 일부 픽셀은 포화됐을 수 있다 (고친 정답 REC는 칸 안에 3,300을 넘는 값이 있으면 그 칸을 뺐다) → 한계
  (이 칸들을 채점에서도 뺄지, 그때 채점 문제 수가 몇 개인지는 최종 점검 F1에서 결정)

## 카메라별 색 변환 오차 (Y4 확인, 2026-10-28)
- 색 변환 ΔE2000 중앙값이 1D 5.03 · 5D 2.55로 1D가 약 2배 → 원인 확인 (보정용 사진만 사용)
- **채널 순서 문제 아님**: Gray World 각도 오차 중앙값 1D 3.35° (R·B 뒤집으면 20.65°),
  5D 3.72° (뒤집으면 13.11°) → 두 카메라 모두 `read_rgb` 순서가 정답 파일과 맞음
- 참고: 24칸 값에서 R·B를 바꿔 행렬을 다시 맞추는 방법은 확인이 안 된다
  (24칸 값과 정답 조명이 함께 바뀌어 3×3 행렬이 흡수함, ΔE 5.032 = 5.032)
- **사진 몇 장 탓이 아님**: 사진별 ΔE 중앙값 — 1D 하위 25% 4.06 · 중앙 4.93 / 5D 중앙 2.54 · 상위 25% 3.42
  → 1D는 잘 맞는 사진도 5D 보통 사진보다 오차가 큼. 오차가 가장 큰 5장 중 3장은 5D
- 결론: 1D 센서가 3×3 행렬로 표준 색에 덜 맞고, 보정용 1D 사진도 29장뿐 → 코드는 그대로 둠
- 영향: 1D 사진은 상한선 정답률도 5D보다 낮을 수 있음 → 리포트에 카메라별 점수를 따로 표기

## 정답 조명의 한계 (Y6 확인, 2026-10-28)
- SFU판 정답 조명은 R·G·B를 **채널마다 따로** 19~24번 중 가장 큰 칸에서 가져온다 (02 검산 방식과 같음)
- Hemrit et al. 2018은 이 때문에 몇 장에서 세 채널이 서로 다른 칸에서 온 문제와, 컬러체커 위치 상자 오류로 생긴
  이상한 정답을 지적하고 고친 정답(REC: 3,300 미만인 가장 밝은 회색 칸 하나에서 R·G·B를 모두 가져옴)을 냈다
- 우리 데이터 확인 (568장 전체, 데이터 값만 봄):
  - 세 채널이 서로 다른 칸에서 온 사진 **3장, 모두 1D**:
    `8D5U5541`(R·G 21번, B 20번, 보정용) · `8D5U5573`(R 19번, G·B 20번, 평가용) · `8D5U5575`(R 22번, G·B 21번, 평가용)
  - 정답에 쓰인 칸의 원본 값이 3,300을 넘는 사진: 0장
- 더 어두운 회색 칸이 더 밝게 측정됨 → 원인 후보: ① 칸 위치(평균 낸 영역)가 틀림
  ② 컬러체커 위에 조명이 고르지 않음(그림자, 한쪽만 밝음). 사진을 직접 봐야 확정 가능 (11번 검수 때 확인)
- `8D5U5541`은 보정용 1D 29장 중 하나이고, 보정용 190장 중 사진별 색 변환 ΔE가 세 번째로 큼(11.1) → 08 행렬에 조금 영향을 줬을 수 있음
- 처리: 3장을 표시해 두고, 최종 리포트에서 "568장 전체"와 "3장 제외" 결과를 함께 보고 (decisions.md D9)

# 데이터 노트 — SimpleCube++

## 대체 이유
- 원래 계획한 Cube+는 배포 링크(SharePoint)가 만료되어 받을 수 없음 (2026-10-28 확인)
- 같은 카메라(Canon 550D)·기준 물체(SpyderCube)로 만든 후속판 SimpleCube++로 대체
- 출처: Zenodo record 4153431, CC BY 4.0

## 구성
- train 1,772장 · test 462장 = 2,234장 (공식 분할 그대로 사용)
- 432×648, 16비트 PNG (원본 대비 4배 축소)
- 포함: Cube 516 · Cube+ 확장 403 · Cube++ 확장 1,315 (`ds_version` 0.0/1.0/2.0)
- 조명 정답 `gt.csv`: `mean_r, mean_g, mean_b` (합 = 1), 사진 이름으로 짝지음 → 1:1 일치 확인

## 처리 규칙 (평가 전 고정)
- 블랙 레벨 2048 (0이 아닌 픽셀 최솟값 1965, 중앙값 2065로 확인)
- 오른쪽 아래(행 182~431, 열 473~647 근처) 큐브 자리가 0으로 칠해져 있음 (평균 15.6%)
  → **블랙 레벨을 빼기 전에** 세 채널 모두 0인 픽셀을 마스크로 표시하고 계산에서 제외
- 포화: 가장 흔한 최댓값 15,303 → 어느 채널이든 15,000 이상인 픽셀 제외

## 한계
- 조명이 하나인 장면만 담음 → 섞인 조명은 이 평가에 포함되지 않음
- 야간 5장뿐 → 야간 그룹 평가 불가. 그룹은 자연광/인공조명(109장), 실외/실내(379장)로 나눔
- `illumination = mixed` 7장, `unknown` 다수 → 그룹 평가에서 제외
