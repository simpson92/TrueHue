# 데이터 노트 — Gehler-Shi (SFU 재처리판)

## 구성
- PNG 568장, 선형 12비트(uint16에 저장)
- Canon 1D 86장(`8D5U…`, 1359×2041, 블랙 레벨 0) / Canon 5D 482장(`IMG_…`, 1460×2193, 블랙 레벨 129)
- 정렬 순서 = 1D 86장 → 5D 482장 (설명서 순서와 일치)
- `colourchecker_gamma1_bit12.mat`: 사진별 24칸 평균 색 (568×24×3, 블랙 레벨 미적용)
- `real_illum_568..mat`: 사진별 조명 정답 (568×3)
- 정답 조명 = (24칸 − 블랙 레벨)의 19~24번 칸 채널별 최댓값(NaN 제외) → 재계산 오차 0 확인

## 빈칸(NaN)
- 1,204칸이 칸 통째로 비어 있음 → 채점 가능 12,428 / 13,632 (91.2%)
- 모든 사진에 쓸 수 있는 칸이 남음 (사진당 빈칸 최대 22개)
- 5D(61% 사진)에 1D(26%)보다 훨씬 많음
- 검정 304 · 파랑 161 · 빨강 105 등 "가장 어두운 채널"이 약한 칸에 집중
- **규칙 확인**: 블랙 레벨을 뺀 뒤 가장 어두운 채널이 20 미만인 칸을 비운 것
  (남은 칸의 최솟값이 1D·5D 모두 정확히 20.0) → 신호가 전체의 약 0.5% 미만인 칸 제외
- 5D에 빈칸이 많은 것은 같은 기준에서 5D 장면이 더 어두웠기 때문

## 처리 규칙 (평가 전 고정)
- 빈칸 칸만 채점 제외, 사진은 568장 유지
- 리포트에 색별 채점 가능 문제 수 함께 표기
- 한계: 빈칸이 어두운 색에 몰려 정답률이 실제보다 높게 나올 수 있음
- 앱에서도 같은 기준 적용 검토: 가장 어두운 채널 < 20이면 "판단 불가"로 답하기

# 데이터 노트 — SimpleCube++

## 대체 이유
- 원래 계획한 Cube+는 배포 링크(SharePoint)가 만료되어 받을 수 없음 (2026-10-28 확인)
- 같은 카메라(Canon 550D)·기준 물체(SpyderCube)로 만든 후속판 SimpleCube++로 대체
- 출처: Zenodo record 4153431, CC BY 4.0

## 구성
- train 1,772장 · test 462장 = 2,234장 (공식 분할 그대로 사용)
- 432×648, 16비트 PNG (원본 대비 4배 축소)
- 포함: Cube 516 · Cube+ 확장 403 · Cube++ 확장 1,315 (`ds_version` 0.0/1.0/2.0)
- 조명 정답 `gt.csv`: `mean_r, mean_g, mean_b` (합 = 1), 사진 이름으로 짝지음 → 1:1 일치 확인

## 처리 규칙 (평가 전 고정)
- 블랙 레벨 2048 (0이 아닌 픽셀 최솟값 1965, 중앙값 2065로 확인)
- 오른쪽 아래(행 182~431, 열 473~647 근처) 큐브 자리가 0으로 칠해져 있음 (평균 15.6%)
  → **블랙 레벨을 빼기 전에** 세 채널 모두 0인 픽셀을 마스크로 표시하고 계산에서 제외
- 포화: 가장 흔한 최댓값 15,303 → 어느 채널이든 15,000 이상인 픽셀 제외

## 한계
- 조명이 하나인 장면만 담음 → 섞인 조명은 이 평가에 포함되지 않음
- 야간 5장뿐 → 야간 그룹 평가 불가. 그룹은 자연광/인공조명(109장), 실외/실내(379장)로 나눔
- `illumination = mixed` 7장, `unknown` 다수 → 그룹 평가에서 제외
